# Ch05 核心概念：工作空间与功能包

> 来源：《ROS2 入门 21 讲》古月居 · 概念总览 + 2.1 工作空间 + 2.2 功能包

**工作空间（Workspace）是存放机器人项目开发相关文件的文件夹，是开发过程的大本营；功能包（Package）是功能代码的基本组织单元，是 ROS 软件复用的核心机制。** 从命令行调试走向真正的工程开发，第一步就是理解这两样东西。

## ROS2 核心概念总览

ROS2 的应用开发围绕一组核心概念展开，它们构成了 ROS 的"世界观"：

![[attachments/c2ov_image-20220523114814371.png]]

**节点（Node）** 是 ROS2 中最基本的执行单元——一个机器人应用就是许多节点协作的结果（一个节点控制电机、一个节点处理摄像头、一个节点规划路径）。节点之间通过不同的通信方式协作：

- **话题（Topic）**：节点间"发布/订阅"式通信，数据单向、异步、多对多；
- **服务（Service）**：客户端/服务器式通信，一问一答、同步、一对多；
- **动作（Action）**：适合耗时任务的通信，带进度反馈与可取消机制；
- **参数（Parameter）**：节点运行时的全局配置。

后续教程会一一详解这些概念。本章先把它们的**工程载体**——工作空间和功能包——建起来。

## 工作空间是什么

使用过 Visual Studio、Eclipse、Qt Creator 等 IDE 的同学，对"创建新工程"不陌生：点击后生成一个文件夹，后续所有工作文件都放里面。类似地，在 ROS 开发中，各种代码、参数、脚本也需要放在一个文件夹里管理，这个文件夹就叫 **工作空间**。

ROS2 中一个典型的工作空间结构如下，`dev_ws` 是根目录，包含四个子目录（四个子空间）：

![[attachments/r21_image-20220524111415729.png]]

| 目录 | 名称 | 作用 |
|------|------|------|
| **src** | 代码空间 | 编写代码、脚本，人为放置到这里（**绝大多数操作在这里**） |
| **build** | 编译空间 | 保存编译过程产生的中间文件 |
| **install** | 安装空间 | 放置编译得到的可执行文件和脚本（编译成功后就执行这里的结果） |
| **log** | 日志空间 | 保存编译和运行中的各种警告、错误、信息日志 |

**工作空间名称可自定义，数量也不唯一**——可以为不同机器人、不同功能建立多个并列的工作空间（如 `dev_ws_a` 用于 A 机器人、`dev_ws_b` 用于 B 机器人）。

## 创建工作空间

```bash
$ mkdir -p ~/dev_ws/src
$ cd ~/dev_ws/src
$ git clone https://gitee.com/guyuehome/ros2_21_tutorials.git
```

`mkdir -p` 一次性创建多级目录，然后进入 `src` 下载课程源码。

## 自动安装依赖

从社区下载的代码多少会有依赖，可以手动逐个安装，也可以用 **rosdep** 工具自动安装（国内推荐使用 rosdepc 镜像）：

```bash
$ sudo apt install -y python3-pip
$ sudo pip3 install rosdepc
$ sudo rosdepc init
$ rosdepc update
$ cd ..
$ rosdepc install -i --from-path src --rosdistro humble -y
```

## 编译工作空间

依赖安装完成后，使用 **colcon** 编译：

```bash
$ sudo apt install python3-colcon-ros
$ cd ~/dev_ws/
$ colcon build
```

编译成功后，工作空间中会自动生成 `build`、`log`、`install` 文件夹。

![[attachments/r21_image-20220524111804569.png]]

## 设置环境变量

编译成功后，为了让系统能找到功能包和可执行文件，需要设置环境变量：

```bash
$ source install/local_setup.sh                          # 仅在当前终端生效
$ echo " source ~/dev_ws/install/local_setup.sh" >> ~/.bashrc   # 所有终端生效
```

至此，工作空间的创建、编译和配置全部完成。

## 功能包：开发过程的大本营

在下载的教程代码中，有很多不同名称的文件夹，它们在 ROS2 中并不是普通文件夹，而是叫 **功能包（Package）**。

每个机器人可能有很多功能——移动控制、视觉感知、自主导航。如果把所有功能源码都放到一起，当想分享其中某些功能时，就会发现代码混合到一起，很难拆分。

![[attachments/r22_image-20220606103223675.png]]

用豆子来比喻：手上有红豆、绿豆、黄豆，都放一个袋子里，想拿出黄豆就得一颗颗挑；把不同颜色的豆子分装到三个袋子，需要哪种立刻就能拿出来。**功能包就是这个原理**——把不同功能的代码划分到不同功能包，尽量降低耦合，分享时只需说明使用方式，别人很快就能用起来。**功能包机制是提高 ROS 软件复用率的重要方法之一。**

## 创建功能包

创建功能包的命令：

```bash
$ ros2 pkg create --build-type <build-type> <package_name>
```

- **pkg**：功能包相关的功能；
- **create**：创建功能包；
- **build-type**：指定是 C++ 还是 Python——C++/C 用 `ament_cmake`，Python 用 `ament_python`；
- **package_name**：功能包名字。

示例：

```bash
$ cd ~/dev_ws/src
$ ros2 pkg create --build-type ament_cmake learning_pkg_c        # C++
$ ros2 pkg create --build-type ament_python learning_pkg_python  # Python
```

## 编译功能包

编写完代码后，需要编译并配置环境变量才能运行：

```bash
$ cd ~/dev_ws
$ colcon build                            # 编译工作空间所有功能包
$ source install/local_setup.bash
```

## 功能包的结构

如何判断一个文件夹是否是功能包？来看新创建功能包的结构。

### C++ 功能包

C++ 功能包必然存在两个文件：**package.xml** 和 **CMakeLists.txt**。

![[attachments/r22_image-20220524112122164.png]]

- **package.xml**：功能包的"身份证"，包含版权描述和各种依赖声明；

![[attachments/r22_image-20220524112141298.png]]

- **CMakeLists.txt**：编译规则。C++ 代码需要编译才能运行，必须在此文件中用 CMake 语法设置如何编译。

![[attachments/r22_image-20220524112132626.png]]

### Python 功能包

Python 是解释型语言，不需要编译，但也有两个关键文件：**package.xml** 和 **setup.py**。

![[attachments/r22_image-20220524112228806.png]]

- **package.xml**：与 C++ 版本相同，包含版权描述和依赖声明；

![[attachments/r22_image-20220524112246102.png]]

- **setup.py**：包含版权信息，以及 **entry_points** 配置的程序入口（后续编程讲解会介绍使用方法）。

![[attachments/r22_image-20220524112235574.png]]

## 小结

| 概念 | 一句话 |
|------|--------|
| **工作空间** | 存放所有开发文件的大本营，含 src/build/install/log 四个子空间 |
| **colcon build** | ROS2 的编译工具，从 src 编译到 install |
| **rosdepc** | 自动安装功能包依赖的工具（国内镜像） |
| **功能包** | 功能代码的基本组织单元，C++ 看 package.xml+CMakeLists.txt，Python 看 package.xml+setup.py |
| **ros2 pkg create** | 创建功能包的命令 |

有了工作空间和功能包，就能开始编写第一个 ROS2 节点，进入"节点 → 话题 → 服务 → 动作"的核心概念实战。
