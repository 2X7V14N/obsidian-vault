# Ch05 深度学习计算

> 来源：《动手学深度学习 2.0》第 5 章（5.1~5.6 完整）

前三章累计写了逐行实现线性回归、从零搭 MLP、手写 ReLU 和 Dropout——代码量不断膨胀，但模式开始重复：定义层 → 堆叠 → 初始化 → 前向传播 → 反向传播 → 更新参数。第 5 章从"功能实现"升维到"架构抽象"——它不教你写新的模型，而是教你**理解深度学习框架的设计哲学**：为什么模型是 `nn.Module` 的子类？参数如何管理？数据如何在 CPU 和 GPU 之间流动？如何保存和加载一个训练好的模型？这些问题贯穿所有后续章节的工程实践。

## 5.1 层和块：神经网络的积木

### 从单一神经元到块的抽象

回顾之前的学习路径：从单个神经元（线性回归）→ 一整个层（Softmax 回归）→ 多层感知机（MLP）。每一层都接受输入、产生输出、拥有一组可调参数。但随着网络变复杂——比如 ResNet-152 有数百层——管理单个"层"变得不可行。

自然的抽象升级是**块（Block）**：一个可以包含多个层甚至其他块的容器。在 PyTorch 中，块由 `nn.Module` 类表示。它可以是：

- 单个层（`nn.Linear`）
- 由多个层组成的组件（`nn.Sequential`）
- 整个模型本身（你定义的 `MLP` 类）

这个设计是**递归的**：一个块可以由许多子块组成，子块可以再包含子块——你可以用简洁的代码构建任意复杂的网络。形象地说，整个神经网络就是一棵树，`nn.Module` 是树的节点，叶子是带参数的层（`nn.Linear`、`nn.Conv2d`），中间节点是容器（`nn.Sequential` 或自定义块）。

![[attachments/blocks.svg]]

### Sequential：流水线

`nn.Sequential` 是最简单的块——一个有序的模块列表，依次执行：

```python
net = nn.Sequential(nn.Linear(20, 256), nn.ReLU(), nn.Linear(256, 10))
X = torch.rand(2, 20)
net(X)  # 等价于 net.__call__(X)，内部依次调用每个子模块的 forward
```

`net(X)` 的背后发生了什么？Python 的 `__call__` 方法在 `nn.Module` 中被重载，它先做准备工作（如设置 training/eval 模式），再调用你的 `forward` 方法。而 `Sequential.forward` 的逻辑极其简单——遍历子模块列表，每个的输出作为下一个的输入。

### 每个块必须提供的基本功能

一个 `nn.Module` 子类必须承担以下职责：

1. 接受输入数据作为前向传播的参数
2. 通过 `forward()` 生成输出（输出形状可以和输入完全不同）
3. 计算输出关于输入的梯度——自动微分引擎自动完成
4. 存储和访问前向传播所需的参数（在 `__init__` 中注册子模块或 `nn.Parameter`）
5. 按需初始化模型参数

### 自定义块：一个 MLP 从零写起

任何自定义块只需继承 `nn.Module`，实现 `__init__`（声明层）和 `forward`（定义前向传播）。至于反向传播和参数初始化——系统自动生成。

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()                        # 必须调用父类构造
        self.hidden = nn.Linear(20, 256)          # 声明子模块
        self.out = nn.Linear(256, 10)

    def forward(self, X):
        return self.out(F.relu(self.hidden(X)))   # 定义计算流程

net = MLP()
net(X)   # 自动调用 forward，自动跟踪梯度
```

两个关键细节不容忽视：**`super().__init__()`** 告诉 PyTorch 这是一个 `nn.Module`，框架会接管参数跟踪、设备移动（`.to(device)`）、序列化等基础设施。如果你忘了调用它，`net.parameters()` 将返回空列表——梯度永远不会更新。其次，**将子层注册为实例属性**（`self.hidden = ...`）而不是局部变量——`nn.Module` 会遍历 `__dict__` 查找所有 `nn.Module` 类型的属性，将它们自动纳入 `_modules` 字典。

### MySequential：理解 Sequential 的内部

手写一个简化版 `Sequential` 能揭示其工作原理：

```python
class MySequential(nn.Module):
    def __init__(self, *args):
        super().__init__()
        for idx, module in enumerate(args):
            self._modules[str(idx)] = module    # 存入 OrderedDict

    def forward(self, X):
        for block in self._modules.values():     # 按插入顺序执行
            X = block(X)
        return X
```

关键在 `_modules`——这是一个 `OrderedDict`，PyTorch 的 `nn.Module` 用它来跟踪所有子模块。把模块存入 `_modules`（而非普通 Python 列表）后，`net.parameters()`、`net.to(device)`、`net.state_dict()` 等方法会自动递归遍历所有这些子模块。如果用普通 `list` 存储，这些功能全部失效。

### 前向传播中的任意代码

`Sequential` 适用于线性流水线，但不是所有架构都是顺序的。自定义块可以在 `forward` 中执行任意 Python 代码——控制流、常数参数、层复用：

```python
class FixedHiddenMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.rand_weight = torch.rand((20, 20), requires_grad=False)  # 不参与梯度
        self.linear = nn.Linear(20, 20)

    def forward(self, X):
        X = self.linear(X)
        X = F.relu(torch.mm(X, self.rand_weight) + 1)   # 使用固定权重
        X = self.linear(X)                                # 复用同一个层！
        while X.abs().sum() > 1:                          # 控制流
            X /= 2
        return X.sum()
```

这段代码展示了三个超越 `Sequential` 的能力：`requires_grad=False` 创建常数参数（反向传播不会更新它），同一个 `self.linear` 被调用两次实现了**参数共享**，while 循环展示了前向传播中可以有任意 Python 控制流。你可以像搭乐高一样嵌套块——一个块里包含 Sequential，Sequential 里又包含自定义块——组合爆炸出无限可能的架构。

### 效率考量

读者可能会担心：这些 `_modules` 字典查找、Python 控制流、自定义 forward 代码——在 GPU 等待 CPU 执行 Python 的过程中，会不会有大量的性能损耗？以 PyTorch 为代表的"Define-by-Run"框架对此的回答是：框架的 C++/CUDA 后端在最底层执行实际计算（矩阵乘法、卷积等），而 Python 层只负责描述"做什么"和"以什么顺序做"。网络越深、每层计算量越大，Python 层开销的相对占比就越小。对于极端情况（如 ResNet-152 这种深度网络），框架还提供 `torch.compile` 等 JIT 编译技术来进一步消除 Python 开销。

## 5.2 参数管理：模型的记忆

训练结束后，模型的价值就是它学到的参数。第 5.2 节回答"如何访问、初始化和共享这些参数"——这些操作在调试、模型复用、迁移学习中是家常便饭。

### 访问参数

`Sequential` 模型可以像列表一样索引：`net[2]` 返回第三个子模块。每个层的参数通过 `state_dict()` 或直接属性访问：

```python
net = nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 1))
print(net[2].state_dict())
# {'weight': tensor([[...]]), 'bias': tensor([...])}

print(net[2].bias.data)         # 访问偏置的值
print(net[2].weight.grad)       # 访问梯度（训练前为 None）
```

在 PyTorch 中，参数是 `nn.Parameter` 类的实例——一个包装了张量的对象，包含值（`.data`）、梯度（`.grad`）和元信息。`requires_grad=True` 是默认的，告诉 autograd 需要追踪这个张量的操作以计算梯度。

**一次性访问所有参数**：`net.named_parameters()` 返回一个生成器——`('0.weight', param)` 这样的名称-参数对。对于嵌套块，名称反映了层级结构：`'0.block1.0.weight'`。

**从嵌套块收集参数**：在复杂网络中，`net.state_dict()` 递归遍历 `_modules` 树，返回所有参数的扁平化字典。这使得保存/加载、参数分析、迁移学习变得极其方便。

### 参数初始化

Ch04 的 4.9 节从数学上推导了 Xavier 初始化的必要性。框架层面，`nn.init` 模块提供了所有常用初始化方法：

```python
def init_normal(m):
    if type(m) == nn.Linear:
        nn.init.normal_(m.weight, mean=0, std=0.01)  # 高斯初始化
        nn.init.zeros_(m.bias)                        # 偏置清零

net.apply(init_normal)  # 递归作用于所有子模块
```

`net.apply(fn)` 是批量初始化的标准方式——它深度优先遍历模块树，对每个节点调用 `fn`。`nn.init` 中的函数名以 `_` 结尾（如 `normal_`）表示原地修改（in-place），遵循 PyTorch 的命名惯例。

**自定义初始化**：当框架提供的初始化方法不够用时，自定义逻辑也很简单：

```python
def my_init(m):
    if type(m) == nn.Linear:
        nn.init.uniform_(m.weight, -10, 10)
        m.weight.data *= m.weight.data.abs() >= 5   # 只保留绝对值>5的值，其余清零

net.apply(my_init)
```

**直接赋值**：你也可以直接修改 `.data` 属性（`net[0].weight.data[:] += 1`），但在 autograd 活跃时需使用 `.data` 以避免被计算图追踪。

### 参数绑定：共享权重

有时我们希望多个层共享同一组参数——例如在 Siamese 网络或 NLP 的嵌入层中。在 PyTorch 中，直接引用同一个 `nn.Module` 实例即可：

```python
shared = nn.Linear(8, 8)
net = nn.Sequential(nn.Linear(4, 8), nn.ReLU(),
                    shared, nn.ReLU(),
                    shared, nn.ReLU(),      # ← 和上面使用同一个 shared 实例
                    nn.Linear(8, 1))
```

第三层和第五层不仅是值相等——它们是**同一个 Python 对象**。修改其中一个，另一个自动同步。反向传播时，两个位置的梯度会**累加**——这对优化器来说意味着一次更新考虑到参数在所有使用位置的贡献。这也是为什么 "weight tying" 是合理的：绑定的参数从多个信号源接收梯度，学到的是综合了所有位置信息的表示。

## 5.3 延后初始化：为什么没指定输入维度也能跑？

回顾之前的所有代码——定义 `nn.Linear(20, 256)` 时我们明确指定了输入维度 20。但如果网络的第一层写在某个函数里，调用时才知道输入是多少呢？PyTorch 实际上采用的是**即时初始化**——在 `__init__` 中创建层时就必须知道全部维度。这是 PyTorch"Define-by-Run"哲学的体现：一切在运行时确定，不留未解决的符号变量。

但在 MXNet 这类框架中，延后初始化（Deferred Initialization）是一个核心设计：定义网络时无需知道输入维度，框架将 `-1` 作为占位符，直到第一批数据通过模型时才完成初始化。这是**框架设计哲学的分野**：

- **PyTorch 风格**：在 `__init__` 中明确所有维度，代码更显式，出错时堆栈跟踪更清晰，用户对自己的模型有完全的控制。
- **MXNet/JAX 风格**：可以推迟维度指定，编写更灵活的层工厂函数，对卷积网络特别方便（全连接层的维度取决于卷积层输出大小，而手动计算这个数字既繁琐又容易出错）。

在实际的 PyTorch 开发中，`nn.LazyLinear` 提供了类似延后初始化的能力——你只指定输出维度，输入维度在第一次前向传播时自动推断。不过在大规模项目中，显式指定维度仍然是主流——它让模型定义自文档化，也让静态分析工具能检查维度不匹配。

## 5.4 自定义层：当标准库不够用时

`nn.Linear`、`nn.ReLU`、`nn.Conv2d`……框架提供了数百种层。但总会有那么一天，你需要一个框架中没有的层。第 5.4 节教你如何从零定义它——而且定义好后，它和内置层的使用方式完全一致。

### 不带参数的层：CenteredLayer

每个层的输出减去其均值——一个简单但有意义的操作。不需要参数，只需 `forward`：

```python
class CenteredLayer(nn.Module):
    def forward(self, X):
        return X - X.mean()
```

它可以像 `nn.ReLU` 一样插入到 `Sequential` 中作为组件——因为它继承了 `nn.Module`，框架自动处理设备移动、序列化等基础设施。

### 带参数的层：MyLinear

自定义带参数的全连接层需要两个要素：用 `nn.Parameter` 包装张量（告诉 PyTorch"这是模型参数，请追踪它的梯度"），在 `forward` 中定义计算：

```python
class MyLinear(nn.Module):
    def __init__(self, in_units, units):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(in_units, units))
        self.bias = nn.Parameter(torch.randn(units,))

    def forward(self, X):
        return F.relu(torch.matmul(X, self.weight.data) + self.bias.data)
```

`nn.Parameter` 是理解 PyTorch 参数管理的关键。它继承自 `Tensor`，但有一个特殊的行为：当它被赋值给 `nn.Module` 的属性时，自动被注册到模块的 `_parameters` 字典中。此后，`net.parameters()`、`net.to(device)`、`optim.SGD(net.parameters())` 都会自动包含这个参数——你不需要手动做任何事情。

自定义层可以像内置层一样用 `Sequential` 堆叠、用 `net.apply` 初始化、在 GPU 上运行。这是框架设计中最优雅的部分：**你的代码和框架开发者的代码享有同等的"一等公民"地位**。

## 5.5 读写文件：让模型活过训练周期

训练一个模型可能需要几小时甚至几天。如果在第 99 个 epoch 断电后一夜回到解放前——这就是为什么要学会保存和加载。模型持久化是工程实践的基本功。

### 单个张量的保存与加载

```python
x = torch.arange(4)
torch.save(x, 'x-file')       # 保存
x2 = torch.load('x-file')     # 加载 → tensor([0, 1, 2, 3])
```

`torch.save` 可以保存任意 Python 对象——单个张量、张量列表、甚至字符串到张量的字典（`{'x': x, 'y': y}`）。底层使用 Python 的 pickle 序列化协议，因此对 Python 对象的兼容性非常广泛。

### 保存和加载整个模型

关键区分：**保存的是参数（state_dict），不是模型架构本身。** 模型可能包含任意 Python 代码（if 语句、循环、自定义逻辑），这些无法被 pickle 正确序列化。因此标准做法是：

**保存**：
```python
torch.save(net.state_dict(), 'mlp.params')
```

**加载**：
```python
clone = MLP()                                    # 重新构造同样的架构
clone.load_state_dict(torch.load('mlp.params'))  # 加载参数
clone.eval()                                     # 切换到推理模式
```

验证：相同输入 → 相同输出（逐元素 `==` 全为 `True`）。

这个设计的一个推论是：**架构定义必须保存在代码中**。当你分享一个训练好的模型时，你分享两类文件：（1）`.py` 文件中的模型类定义，（2）`.params` 文件中的训练好的权重。两者缺一不可。`torch.save(net, 'model.pt')` 虽然技术上可行（保存整个 Module 对象），但在生产环境中不推荐——它依赖 pickle，在加载时需要原始类定义在同一路径下，跨环境可移植性差。

## 5.6 GPU：让计算飞起来

自 2000 年以来，GPU 性能每十年增长约 1000 倍——深度学习今天的繁荣很大程度上建立在 GPU 的算力之上。第 5.6 节带你了解 PyTorch 的 GPU 编程模型。

### 计算设备

PyTorch 用 `torch.device` 抽象计算设备：

```python
torch.device('cpu')           # CPU
torch.device('cuda')          # GPU 0（等同于 'cuda:0'）
torch.device('cuda:1')        # GPU 1
torch.cuda.device_count()     # 查询可用 GPU 数量
```

安全地编写设备无关代码的模式——如果 GPU 可用就使用，否则回退 CPU：

```python
def try_gpu(i=0):
    if torch.cuda.device_count() >= i + 1:
        return torch.device(f'cuda:{i}')
    return torch.device('cpu')
```

### 张量的设备语义

张量始终在某个设备上创建。默认是 CPU：`x = torch.tensor([1, 2, 3])` → `x.device` → `cpu`。要放到 GPU 上：

```python
X = torch.ones(2, 3, device=try_gpu())   # 创建时指定设备
X = X.cuda(1)                              # 移动到 GPU 1
```

**铁律：参与同一计算的所有张量必须在同一设备上。** `cpu_tensor + cuda_tensor` 会抛出运行时错误——框架不知道应该把结果放在哪里。必须先显式移动数据。

![[attachments/copyto.svg]]

**数据搬运比计算慢得多**。CPU ↔ GPU 之间的数据传输是深度学习中最常见的性能瓶颈。黄金法则：**让数据在 GPU 上流动，只在必要时才搬回 CPU**。`net(X)` 如果 `net` 和 `X` 都在 GPU 上，计算全程零拷贝。如果 `X` 在 CPU 而 `net` 在 GPU，每一轮前向传播之前都必须把输入搬到 GPU——批大小越大，这个开销越显著。

### 神经网络与 GPU

把整个模型搬到 GPU 只需一行：

```python
net = nn.Sequential(nn.Linear(3, 1))
net = net.to(device=try_gpu())    # 所有参数和缓冲区一次性移动
```

`net.to(device)` 递归遍历 `_modules` 和 `_parameters` 树，将所有张量参数移到目标设备。模型在哪个设备，计算就在哪个设备——输入数据在 GPU 上时，前向传播和反向传播全程在 GPU 执行。你不需要手动管理数据流——只要确保三件事在同一设备上：**模型参数、输入数据、目标标签**。

`nvidia-smi` 命令可以查看 GPU 显存使用情况、温度、功率和计算利用率——是调试 GPU 程序的必备工具。

## 小结

第 5 章是 Ch01~Ch04 的"元认知"升级——它不教你新模型，而是教你理解模型是如何被框架管理和执行的。

- **块抽象**（`nn.Module`）：所有神经网络的基类。`__init__` 声明层，`forward` 定义计算流，框架接管梯度、参数和设备管理。`Sequential` 是有序块的容器。
- **参数管理**：通过 `state_dict()` 访问所有参数，通过 `nn.init` 初始化，通过 `.apply(fn)` 批量操作。`nn.Parameter` 是参数与普通张量的分界线。
- **参数绑定**：同一个 `nn.Module` 实例在多个位置使用时共享参数，梯度自动累加——这是 weight tying 的底层实现。
- **自定义层**：继承 `nn.Module`，用 `nn.Parameter` 声明参数，用 `forward` 定义计算。写好后和内置层完全一样使用。
- **模型持久化**：`.state_dict()` + `torch.save` 保存参数，重新构建架构后 `.load_state_dict` 恢复。架构定义必须留在代码中。
- **GPU 计算**：`.to(device)` 移动模型和数据。同一计算的所有张量必须在同一设备上。数据传输开销远超计算——让数据留在 GPU 上。
